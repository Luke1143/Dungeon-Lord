## 0.4 - View and comfort
- **Layout**: the level fills the window (`#viewport`, resized by a `ResizeObserver`); the side panel is 290 px wide and scrolls on its own, stats sit in a 2-column grid. Below 900 px it stacks. Top bar holds speed, zoom, throne, minimap and menu buttons.

- **Minimap** (`drawMinimap`, key `M`): terrain, rooms, gold, imps, creatures (heroes red) and the visible area; hidden caves stay hidden.

## 0.3 - Campaign skeleton (main menu + overworld)
- **Screens**: `menuScreen` (Neue Welt / Kampagne fortsetzen, optional seed), `overworldScreen`, `levelScreen`. `showScreen(name)` switches; `gameTick` and autosave only run on the level screen.
- **Overworld** (`buildWorld(seed)`): deterministic from the seed, never saved (only `{seed,pos,visited,levelNode,inLevel}` goes to `dungeon-lord-campaign-v1`). 80x45 tiles from three value-noise layers (water, grass, forest, hills, mountain, swamp).
- **Nodes**: `OW_TURNS` (9) columns left to right, 1 / 2-3 / ... / 1 nodes; column 0 is the river village, the last one the capital. Terrain under a node picks its type from `LOCATION_TYPES` (table: label, description, side goal, name suffixes). Edges lead to the next column; every node is reachable.
- **Flow**: click a glowing node -> "Angreifen" -> `startLevel(nodeId)`. Win -> `finishLevel()` returns to the map, capital won -> back to menu. Loss -> run deleted (permadeath), back to menu. "Level neu starten" restarts the current level.
- **Difficulty**: `state.war.difficulty` = column index; `spawnWave` adds it to the wave number for size, hero level and hero types.
- Location types so far only change name and text; level generation per type (roots, dwarf structures, rivers) is still to do.

## 0.2 - Game loop (war)
- **Weltportal** (`portal` room, 2x2, placed 30+ tiles from the throne, not buildable/demolishable). Conquering all portal tiles = **victory**.
- **Waves**: as soon as a walkable path from portal to throne exists (`portalConnected`, checked every 5 ticks), heroes spawn at the portal. First wave after 150 ticks, then every `max(180, 340 - 12*wave)` ticks. Wave size `1 + 0.8*wave` (max 10), hero level `1 + (wave-1)/2`.
- **Heroes** (faction `good`, category `hero`): Barbar, Dieb, Zauberer (wave 3+), Ritter (wave 5+). They fight hostiles within 8 tiles, otherwise march to the throne (`tickHero`). They never flee. Killing a hero pays a bounty (30 gold per level).
- **Defeat**: heroes standing in the throne room reduce `war.throneHp` (strength x 0.25 per tick); it regenerates when no hero is inside. 0 = defeat.
- End overlay with "Neues Spiel"; simulation freezes when `war.over` is set.
- Saves use `localStorage` when `window.storage` (Claude artifact API) is missing. Key `dungeon-lord-v1`.
- Cleanup: removed duplicate `forge`/`arena` table entries; state creation unified in `makeDefaultState()`.

**Not balanced yet** - needs playtesting (wave strength vs. defenders, throne damage rate).

## 0.7 3D view in the game
- `view3d.js` is a second renderer for the level (Three.js, loaded on demand from `lib/`). Toggle with the `3D` button or `V`; the choice is remembered. Q/E rotate the camera, WASD and middle-drag pan relative to it, the wheel zooms, the minimap and all clicks work as before.
- How it works without touching the game rules: `draw()` in 3D mode runs the old 2D drawing on a throwaway canvas while `capture` collects every sprite, prop and emoji the 2D code wants to draw (position, scale, offsets); `View3D.render` turns that list into billboards and ground decals. Terrain comes from `tileInfo3d(x,y)` (walls as blocks with the tile texture, floors/water as planes). Marks, queued rooms, room selection and the drag rectangle are drawn on the transparent 2D canvas above, projected with `View3D.project`. Picking uses a ray against the tile meshes (`tileFromEvent`).
- Known gaps: the metal pipeline is only approximated (ingots as the ingot sprite, ore piles as emoji), no torch light or shadows yet, effects and thoughts are plain emoji billboards, bridges still look like water, the camera pitch and wall contrast are first guesses, and it has only been checked with software rendering.
- 3D lights: torches, candles, fires, kilns and furnaces cast warm flickering point lights (the eight nearest to the camera, `LIGHT_KEYS` in `view3d.js`).

## 0.9 Balance check (tools/balance-sim.js)
- `NODE_PATH=$(npm root -g) node tools/balance-sim.js [maxTicks]` runs the level headless (Playwright + Chromium): it digs a corridor from the portal to the throne, puts a fixed set of defenders (none/small/medium/large) in the throne room, removes the imps and calls `gameTick()` until the throne falls. Math.random is seeded, so runs repeat.
- First results (throne 100 hp, 350 ms per tick, first wave 150 ticks after the break-through, no traps, no healing, no imps):
  - Difficulty 0: none 374 ticks (wave 1), small 1210 (wave 4), medium 1488 (wave 5), large 1758 (wave 6).
  - Difficulty 2: wave 1 / 2 / 3 / 4 for none / small / medium / large.
  - Difficulty 4 and up: the throne falls in wave 1 even against the large set (diff 8: 8 level-5 heroes in the first wave).
  - Finding: with imps, **one imp conquers the portal about 65 ticks after the corridor opens, well before the first wave (150 ticks)**. Waves never matter if the player rushes. Needs a design decision (longer conquest, conquest blocked while heroes are near, shorter first wave, or something else).
  - Finding: difficulty is added in full to the wave number, so late turns start with wave-9 strength.

## 1.0 Imps, scouts, effects
- **Imp bug fixed**: imps flipped between "waits for work" and "picks up gold" forever when a pile existed but no reachable store accepted gold (storage filter off, room walled off, store full of other goods). `findHaulJob` now only takes a pile if `computeStorageSlots('gold')` is not empty, there is room, and `findStorageTile` finds a way; the ore job got the same reachability check. Reproduction was a store with the gold filter off (454 state flips in 500 ticks before, 0 after).
- **Waves and scouts**: `tickWar` runs the wave timer from level start (`WAVE_FIRST_TICKS` 450), no longer only after the portal is connected. When a hero has no walkable way to the throne, `heroDig` follows `digRouteToThrone` (Dijkstra: floor 1, water 2, rock 10, reinforced rock 20, bedrock blocked) and digs with the normal `interact` verb (`recipeFor` lets heroes dig any rock). The hint line shows the countdown to the scouts.
- **fx.js**: particle system with its own PRNG (no influence on seeded runs). `emitFx(type, x, y, opts)` in `index.html`; recipes: chip, dig, claim, reinforce, build, poof, hit. 2D draws them in `drawParticles`, 3D collects them as `particle` items. Dig progress shows as cracks (`TILEGEN.crack`, stages 1-4 from `t.work`), also on the 3D block faces.
- **Torches**: `wallTorchItems()` emits `wallTorch` items (wall direction dx,dy); `View3D` builds a small stick mesh fixed to the wall face and leaning away from it with a flame sprite on top. dx=dy=0 stands upright (floor torch).
- Balance sim with sealed portal and scouts, no imps: throne falls in wave 1-2 from difficulty 4 up even against nine defenders, difficulty 0 lasts until wave 4-5 with a medium set. The sim does not model a real player (no traps, healing, imps, levelling), so treat it as a lower bound.
- **Reinforced walls (tug of war)**: `wallNeutralized(x,y)` compares `wallScores`: player = owned floors (1 each) + imps and player creatures within one tile, enemy = floors with `t.enemy` (0.5 each) + heroes within one tile; enemy must be strictly greater. `recipeFor` gives heroes no dig recipe for a reinforced wall unless neutralized; `digRouteToThrone(c, allowReinforced)` treats a non-neutralized reinforced wall as impassable, `heroDig` falls back to the cheapest route through reinforced walls and waits next to the wall (`state 'probing'`). Heroes mark floors they stand on as `enemy` (red tint in 2D and 3D); an imp's claim clears it. `decayReinforcedWalls()` (every `WAR_CHECK_INTERVAL` ticks) removes the reinforcement from walls that no longer touch owned floor. Heroes never dig diamond fields (they would never break).
- Test: throne ring fully reinforced, no imps, no defenders: the first scout probes the wall (tick ~750), the wave-2 group tips the contest and breaks in (~tick 810-860).
- Sim with the tug-of-war rule, 3 imps, pre-reinforced ring (`node tools/balance-sim.js 3500 3 ring 0,2,4,6`): the throne still falls every time. Difficulty 0 holds until wave 2/3/4/4 for none/small/medium/large defenders (tick ~960/1290/1460/1570); difficulty 2: wave 2-3; difficulty 4: wave 1-4 (only the large set reaches wave 4); difficulty 6: wave 1-2. Defenders mostly die (1-3 of 3-9 left). Conclusion: the walls delay the heroes by a few hundred ticks, but the fights are lost: heroes (levelling every two waves, groups of 3-10) out-fight the starting creatures, so the lever is hero strength / wave size / defender strength, not the walls. Open question for the player: target survival (e.g. wave 5 at difficulty 0, wave 3 at difficulty 4 with a sensible army?).

## 1.1 Combat feel, finite waves
- **Tug of war** now counts territory only (`wallScores`): player = owned floor tiles, enemy = hero-held floor tiles at half weight.
- **Finite pool**: `waveTotal(diff)` = 3 + diff/2 (3..8) waves; `spawnWave` stops after the last one, which adds "Der Ritter" (knight, level + 2, fine hammer, heavy armour, tower shield). Hero level `1 + (wave + diff - 1) / 3`, size `1 + 0.7 (wave + diff)`. `heroGear(kind, level, boss)` gives heroes weapons, armour and shields (tier crude/plain/fine by level). The UI shows `wave/total`, the hint line the countdown or the remaining heroes.
- **Hit feedback**: `resolveAttack` calls `hitFx` (index.html): white silhouette flash (`silhouetteOf`, 130 ms, 2D and 3D), visual knockback away from the attacker (`kbx/kby`, eased in `drawActor`), blood via `FX.blood` (blobs with gravity; they land as floor stains or hit a wall tile and stay as wall stains), gibs and a pool on kills (`FX.gibs`). `BLOOD` table gives the colour per kind (skeleton: bone chips). Stains live 90-170 s, at most 320; drawn by `drawStains` in 2D and as decals in 3D. Effects freeze while the game is paused.
- Visual-only knockback: the creature does not change tiles. A real shove is a possible next step.
- Sim with finite waves, territory-only tug of war (5x5), 3 imps, pre-reinforced ring (`node tools/balance-sim.js 6000 3 ring 0,4`): difficulty 0 (3 waves): none/small/medium lose at tick ~1030/1150/1570, **large holds** (all heroes dead, throne untouched). Difficulty 4 (5 waves): lost at ~660/860/1010/1325 (wave 1-3). Without territory widening the ring was unbreakable (5000 ticks, heroes piled up), so heroes now dig out and take the ground around a wall they cannot break (`heroWiden`) and commit to one siege wall (`c.siege`).

## 1.2 Terrain and wall cost (balance levers)
- Design call: heroes failing to break a perfect ring is not a bug; the balance sim's static defender is the limitation (a real player expands, digs towards gold and takes risks, and may line a deliberate weak point with traps). Levers instead: wall cost, terrain, water.
- `WORK_COST.reinforce` 24 -> 60 (dig stays 10).
- `makeDefaultState` now builds the terrain from `growCaveSystem` (cellular automata caverns, components >= 12 tiles joined by winding tunnels), `growRivers` (1-2 meandering rivers from the top or left edge, width 1-2, never through the throne corner) and `growLake` (0-2 lakes). Water is walkable for heroes, cannot be reinforced and needs bridges for the player. The old blob caves with basins are gone. Quick check: four maps gave 146-276 cave tiles and 67-181 water tiles.
- The balance sim has no real player behaviour; use its numbers only as a lower bound.

## 1.3 World economy (first slice)
- `overworld.js` (`OW`): pure rules, tables for `REGION_TYPES` (production, local level bonus, aura, level-generator parameters, text) and `EVENTS` (dice). Hero power per stat = production of the regions that are still owned by the good side and connected to the capital x time factor (0.5 + 0.12 per round) x alarm (1 + 0.07 per conquered region) + decaying event bonuses (`campaign.bonus`, 25 % fade per round). `levelMods(world, campaign, node)` turns it into waves (3 + fort/3, local, neighbouring fortresses), heroes per wave (food/4), hero level (training/4), gear tier crude/plain/fine/epic (iron thresholds 3/6/10, local forge +1), extra wizards (magic/4). `explainDefeat` builds the text of the loss screen.
- Map (`buildWorld`): 9 columns, region type from the terrain under the node (weighted: grass farmland/village/camp, forest tower/elf forest, hills fortress/camp/mine, mountain forge/mine/fortress, swamp bog), ~16 % empty event places, all six economy types guaranteed, roads are two-way (forward, sideways within a column, occasional shortcuts), `regionOf` assigns each cell to the nearest node.
- Moves: each move (new region, travel through a conquered one, event place) is one round (`owAfterMove`: round counter, 25 % chance of a global event with a dice roll, modal). Conquered regions are scorched and tinted on the map (`owConqueredOverlay`); unknown regions show `?` until adjacent or revealed (spy events). Production badges (dots) show what a known region feeds; hollow = cut off.
- Levels: `startLevel` stores `state.war.mods` and the region's `gen` parameters (`levelGen`: cave density, rivers, lakes, ore/gold veins, bedrock), logs the enemy briefing, `spawnWave` and `heroGear` read the mods. A win marks the region as conquered and gives one skill point (not used yet); a loss shows the explanation in the end overlay.
- Quick check on one seed: a rush through 7 regions left the capital with ~+1 hero, +1 level, +1 wizard and crude gear; taking all producers first (13 rounds) left only the capital's own production. Balance (time factor, alarm, thresholds) is still a first guess; it needs a sim of whole runs.
- `tools/balance-sim.js` now sets a stand-in `state.war.mods` from its difficulty argument.

## 1.4 Gates (step 1)
- Map is 11 columns (`OW_TURNS`). `buildWorld` picks 2 (cols 3 and 7) or 3 (cols 2, 5, 8) gate columns with a single node each, so every road to the capital passes through them; skip roads never jump over a gate column. The gate types are `REGION_TYPES` entries (`gate:true`, `fixedName`, `terrain`, `boss`, `paths: { frontal, cunning }`): `gate_dwarf` (Alberichs Hallen), `gate_elf` (Hain des Weltenbaums, Oberon), `gate_hydra`, `gate_labyrinth`. They are always known on the map, get their own glyph and a gold ring, reshape the terrain around them, deliver big production (iron/magic/fort) and add +2 local waves. Check over 12 seeds: removing any gate disconnects the capital, shortest path 9-10 moves.
- Names stay free myth (Alberich, Yggdrasil, Oberon, Hydra, Minotaur), no Tolkien names.
- Not yet built (steps 2-4): objectives as a table (conquer portal, steal gold, undermine roots, defeat boss), the corruption path (boss joins as a unit), the special gate maps and boss fights, optional levels with effect on a gate, level size and length by stage (10-60 min), rush test over whole runs.
- Known blemishes: on very watery maps nodes shift to the nearest land, so the left-to-right order gets looser and labels may overlap; the info panel of a gate is long.

## 1.5 Goals as a table, first gate (dwarf king)
- `objectives.js`: `GOALS` table (`conquer_portal`, `defeat_boss`, `steal_gold`), each with `label` and `check(state, goal)`. A region type can carry `goals` (and a `setup`); a level with `state.war.goals` is won by any of them (`tickWar`), a level without goals keeps the portal win. `state.war.wonBy` / `wonText` feed the end overlay; the side panel shows the ways with progress (`#goalsBox`).
- `gate_dwarf` (Alberichs Hallen): `setupDwarfHoard()` carves a 5x3 hall far from throne and portal, fills it with gold piles flagged `hoard`, walls it with `reinforced + fixed` rock (fixed walls never decay) and places Alberich (`createBoss('dwarfking')`, level 4, epic hammer/armour/tower shield, +40 hp, drawn 1.25x). Frontal way: kill him (or knock him out). Cunning way: haul 15 units from the hoard into storage; `CARGO.gold` tracks `carryHoard`, taking hoard gold wakes the king (`alert`: he hunts player units), delivering counts as `state.war.stolen`; then `winByGoal` corrupts him (faction evil, home = throne) and the level is won.
- Reward: `campaign.allies` (saved) gets him; every following level `startLevel` spawns him at the throne as an ally (`createBoss(..., faction 'evil')`). Sprites: `ZOO.dwarfking` (white eyes) and `ZOO.dwarfking_ally` (player-side eyes), bronze heavy armour with a visible red beard; `drawCreatureSprite` picks `<kind>_ally` for evil-faction creatures that have one.
- New category `boss` (`SPECIES.dwarfking`), `tickBoss` (guards home, hunts when alerted, boss aggro 7 tiles).
- Checked by script: hall placement 25/25, frontal win, cunning win with ally carried into the next level, hoard counting. Not played by hand. Not built yet: the other three gates' goals (roots, hydra spring, labyrinth thread), boss-specific fight mechanics, optional levels with effects on a gate, ally use in the UI (inspector, wages, food).

## 1.6 Oberon's grove (gate 2)

- Checked by script on one seed: layout (9 tree tiles, 8 roots, 64 moss tiles), six roots win the level with Oberon corrupted and recorded as ally; the 3D view of the grove looks as intended. Not played by hand. Oberon does not heal roots or cast spells yet.

## 1.8 Die Burg der Guten (`keep.js`)
Stufe 1 der Wirtschaft der Guten (siehe `docs/design.md`). Das Weltportal ist Eingang und Thronsaal der Gegner.
- `state.keep` entsteht in `startLevel` per `initKeep(regionType, mods, builder)`; `tickWar` ruft `tickKeep()` statt der alten Wellen-Uhr. `state.war.poolTotal` ist die Größe des endlichen Rekrutenpools (Summe der früheren Wellengrößen), `waveTotal` liefert sie.
- Bauen: `keepBuildRoom` schnitzt 2x2/3x2-Räume neben das Portal (Boden mit `t.goodRoom=<Raumtyp>`, nie direkt an eigenem Land). Räume wirken: Kaserne = mehr Helden gleichzeitig, Vorratskammer = Nahrung (Rekrutentempo), Übungsplatz = Stufe, Schmiede = Ausrüstungsstufe, Zauberschule = Zauberer, Lager = nur Skin.
- Rekrutieren: `keepRecruit` kostet 1 Nahrung, wählt Art/Stufe/Ausrüstung aus Räumen plus `mods`. Letzter Rekrut ist der Ritter (nur ohne Ziele).
- KI-Profile `AI_PROFILES` (panic, cautious, drilled, aggressive, fortified, hyper, greedy) kommen über `REGION_TYPES[...].ai` aus der Weltkarte und stehen im Infofenster. Aggression = Chance, dass ein Rekrut sofort angreift, sonst wartet er als Besatzung (`c.post`, `keepGarrison`), bis genug da sind (Koordination) oder der Pool leer ist (`keepDirector`).
- Oberon (`hyper`, `reacts`): nach jeder gekappten Wurzel `keepOnRootCut`: schnelleres Rekrutieren und Wächter, die sich zu den übrigen Wurzeln graben (`c.guardRoot`, `keepGuardRoot`; `digRouteToThrone` nimmt dafür ein Ziel).
- Erobern: die normale Claim-Regel; `applyRecipe` wandelt `goodRoom` in `room` (Spieler-Skin). Darstellung: Raumtextur mit blauem Tint (2D und 3D).
- Offen: Stufe 2 bis 4 (gemeinsamer Boden, Arbeiter, gespiegelte Bedürfnisse, Kartenboni steuern Startvorrat), Balancing der Profile.

## 1.9 Nebel des Krieges, Wandoptik, Handwerker (Stufe 2)
- Nebel über alles: jede Kachel hat `t.seen` (gespeichert). `updateFog()` (alle 2 Ticks) leuchtet eigenes Land (Radius 2) und eigene Einheiten (Radius 3) aus. Ungesehenes ist schwarz (2D, 3D, Minikarte), nur gesehene Kacheln sind markierbar. Gegner werden nur gezeigt, solange sie im Licht stehen (`state.vis`, `fogHidden`). Alle Zeichenhelfer (drawProp/Emoji/Creature, Partikel, Flecken) fragen `fogHidden`.
- Wände: `wallFaceSpec(base,nx,ny,reinforced)` liefert Ziegel- bzw. Raumwandtextur nur noch für verstärkte Wände. Fackeln hängen nur an verstärkten Wänden (`wallTorchItems`).
- Handwerker (`worker`, Kategorie 'worker', Fraktion good): bauen die Räume der Gegner sichtbar. `keepPlanRoom` wählt einen Bauplatz am Keep, `keepTickWorker` gräbt ihn aus (normales `interact`) und baut (`KEEP_BUILD_WORK`). Fällt ein Handwerker, kommt nach einer Weile ein neuer; ohne Handwerker wächst die Burg nicht. Profile haben `workers` (Dorf 1, Verschanzt/Geizig 3, Oberon 0).
- Geteilter Boden: erobert der Spieler einen Gegnerraum, bleibt `t.wasGood`. Handwerker holen ihn zurück (`KEEP_RECLAIM_WORK`), wenn er am Keep anliegt und keine Spielereinheit im Umkreis 3 steht. Wer den Boden hält, nutzt den Raum.

## 1.10 Gespiegelte Bedürfnisse (Stufe 3)
Wartende Rekruten (Besatzung am Portal, `keepGarrison`) leben wie die Kreaturen des Spielers: sie essen aus dem Vorrat der Burg (`KEEP_UPKEEP`, Vorratskammern füllen ihn), erholen sich in der Kaserne und trainieren im Übungsplatz (Erfahrung, Stufenaufstieg ohne Logmeldung). Ist der Vorrat leer, werden sie hungrig und marschieren nach `KEEP_STARVE_TICKS` ungeduldig los. Wer also Vorratskammer oder Übungsplatz erobert, schwächt die Wartenden. Geduldige Profile (Dorf, Verschanzt) bekommen stärkere Helden, zahlen aber mit Nahrung.

## 1.11 Was die Gegner bauen und können (Stufe 4)
- Jede Regionsart hat `build:[...]` (Dorf: Vorratskammer, Kaserne, Lager; Festung: Kaserne, Übungsplatz, Schmiede ...). `keepRoomPlan(rt,mods)` hängt Räume an, die der Weltfortschritt freischaltet (Rüstung ≥2 → Schmiede, Ausbildung ≥2 → Übungsplatz, Magie ≥1 → Zauberschule, Nahrung ≥2 → zweite Vorratskammer) und kürzt auf `maxRooms` des KI-Profils (+1 ab 5 Wellen). Das Infofenster der Region zeigt den Bauplan.
- Eine entwickelte Region (`mods.waves-3`) startet mit schon gebauten Räumen.
- Technik hängt an Räumen: Zauberer gibt es nur mit Zauberschule, Ritter nur mit Schmiede und `gearTier≥1`; Ausrüstungsstufe wie bisher aus Schmiede und `mods`.
- Das Portal und der Eingang sind nie im Nebel (`updateFog`).

## 1.12 Dungeon Lord und der Zug der Guten
- Der Dungeon Lord (`dungeonlord`, schwarze Plattenrüstung, Stachelkrone, Streitkolben, `MATS.schwarz`, `WEAPONS.keule`) entsteht in `startLevel` am Thron (`spawnDungeonLord`), bewacht ihn wie ein Boss mit `guard` und ist besessen-bar. Fällt er, sammelt er sich nach `LORD_RESPAWN_TICKS` neu (`state.war.lordTimer`). Seine Stufe wächst mit den Fertigkeitspunkten.
- Zug der Guten (`overworld.js`): `alarm` (nach jedem Sieg, Würfel pro Nachbar, Wurf ≥4) und `goodTurn` (bei `advanceRound`). `REGION_TYPES[...].alert`: `'call'` (Dorf, Farmland, Moor, Elfenwald: Bote zur nächsten Festung/Hauptstadt, dort entsteht eine Armee, die zur rufenden Region marschiert und sie verstärkt; ist sie gefallen, jagt sie den Spieler und gibt bei Ankunft `campaign.ambush` = +2 Wellen) oder ein Objekt, das `campaign.fort[id]` (lokale Boni) erhöht. Boten kann der Spieler abfangen (auf seinem Feld). Karte: 📯 Bote, ⚔️ Armee, 🛡️ vorbereitet. `campaign.report` wird in `owAfterMove` als Modal „Der Zug der Guten“ gezeigt.
- Offen: legendäre Helden hören vom Spieler, Armeen als eigene Begegnung, Abfangen von Armeen.

## 1.13 Balance-Lauf mit Gegner-Burgen
`tools/balance-sim.js [maxTicks] [imps] [ring|open] [Schwierigkeiten] [Regionsarten]` simuliert jetzt je Regionsart die Burg der Gegner (Bauplan, KI-Profil). Stand 5000 Ticks, Ring, 3 Imps, Schwierigkeit 2 und 4: Dorf ist gegen mittlere Verteidigung (6 Kreaturen plus Dungeon Lord) zu halten, Festung und Hauptstadt fallen bei Schwierigkeit 4 nach rund 3100 bis 3800 Ticks auch gegen große Verteidigung. Der Simulator hat nur einen statischen Dungeon, feinere Abstimmung braucht echte Spielläufe. Der Nahrungsvorrat der Burg ist auf `KEEP_FOOD_CAP` gedeckelt.

## 1.14 3D-Modelle, Ego-Perspektive, Action-RPG-HUD
- `view3d.js` hat `MODELS` (Boxen mit Pixeltexturen): `bed` und `shelf` ersetzen das Billboard (`placeModel`). Neues Modell = neuer Eintrag in `MODELS` und der Schlüssel in `PROP_OF`; `propFacing` in index.html dreht Dinge mit Rückseite von einer Wand weg. Für Hörner, Truhen usw. gilt dasselbe Muster.
- Besessenheit schaltet in die Ego-Perspektive (`fpActive`: besessen und 3D; ist 3D aus, wird es kurz eingeschaltet und danach wieder ausgeschaltet). `View3D.setFirstPerson({x,y,yaw})` setzt die Kamera auf Augenhöhe (FOV 72, Decke sichtbar). Gelaufen wird auf Kacheln: W/S vor/zurück, A/D seitwärts relativ zur Blickrichtung (auf die nächste Achse gerundet), Q/E oder Maus (Pointer Lock) drehen, gedrückte linke Maustaste schlägt zu oder arbeitet an der Kachel davor (`fpActStep`, pro Tick). Taste 2 = Eile (ab Stufe 5, `HASTE_*`), Esc verlässt.
- HUD `#fpHud`: Lebenskugel, Energiekugel, Aktionsleiste (Zuschlagen, Eile mit Abklingzeit, Verlassen), Name, Stufe, Erfahrungsbalken, Zielanzeige, Fadenkreuz. Die Minikarte ist in dem Modus aus.

## 1.15 Höhlendecke und UI im Spielfenster
- Decke (nur Ego-Perspektive, `buildCeiling` in `view3d.js`): ein Höhenfeld über den Kachelecken. An Wänden liegt sie auf Wandhöhe, mit dem Abstand zur nächsten Wand (Breitensuche über die Ecken) steigt sie in einer Sinuskurve bis +1,8: große Höhlen bekommen eine Kuppel, enge Gänge ein niedriges Gewölbe. Wird neu gebaut, wenn sich Kacheln ändern.
- UI: der Levelbildschirm ist `position:fixed` im ganzen Fenster, die Welt füllt es aus. Titelleiste, Seitenpanel (halbtransparent, Tab oder 🗂 blendet es aus), Hinweiszeile, Kampfleiste und Minikarte schweben darüber. In der Ego-Perspektive sind Panel und Hinweiszeile aus. Schmale Fenster: Panel als untere Leiste.
- Ego-Perspektive blendet den Körper des Besessenen (Waffen-/Rüstungssymbole, Gedanken, Besessenen-Ring) aus, sonst hängen sie riesig vor der Kamera.

## 1.16 Flüssige Bewegung in der Ego-Perspektive
Der Besessene hat in der Ego-Perspektive eine Kommazahl-Position (`c.fx`, `c.fy`, Mittelpunkt in Kacheleinheiten). `fpMove(dt)` läuft pro Bild in `renderLoop` (WASD relativ zur Blickrichtung, Tempo aus `statSpeed`, Eile, Spieltempo; Pause friert ein), kollidiert mit Kacheln (`fpSolid`, Radius `FP_RADIUS`, getrennt in x und y, also Gleiten an Wänden) und weicht anderen Körpern aus. Für die Spiellogik gilt weiter die Kachel `c.x=floor(fx)`, `c.y=floor(fy)`. Zielen: `fpPickTarget` nimmt einen Feind im Kegel vor dir (Reichweite `FP_REACH`), sonst die bearbeitbare Kachel (eigene oder Nachbarkachel) am besten in Blickrichtung; die Zielanzeige nennt Namen oder Aktion. Graben bleibt wie überall an Markierungen gebunden (gleiche Rezepte für alle).

## 1.17 Aktionsanimationen mit festen Regeln (`anim.js`)
- Eine Tabelle `ACT_ANIM` ordnet jedem Verb eine Bewegung zu: Angriff wechselt zwischen `over` (Schlag von oben) und `side` (Schlag von der Seite), Graben ist `over` (Faust grau getönt), Verstärken und Bauen sind kurze `tap`-Schläge (stahlblau, holzbraun), Erobern ist `stomp` (Sprung mit Stampfen, lila), Ziehen ist `lift`. Neues Verb = neue Zeile.
- `swing()` ruft bei jedem tatsächlich ausgeführten Schwung `startAnim` (auch bei Fehlschlag); das Verb kommt aus `interact` (`rec.id`), dem Kampf (`attack`) oder dem Zustand des Wesens (`STATE_VERB`, so auch für Imps). `poseOf(motion,p)` liefert Winkel, Handversatz, Vorstoß, Sprung und Kamerastoß; `currentPose` liest sie aus `actor.anim`.
- Regel: geschwungen wird nur, was wirklich gehalten wird (die Waffe aus dem Inventar, `toolCanvas` aus `TOOLGEN`). Wer nichts hält, schwingt nichts: jeder Schwung hinterlässt nur einen Lichtbogen in der Verbfarbe (`slashCanvas`, `slashAlpha`), wie im Original Dungeon Keeper. Die Waffe im Sprite wird während des Schwungs ausgeblendet (`noWeapon`), damit sie nicht doppelt erscheint.
- Der Dungeon Lord hat keine eingebauten Hände oder Stab mehr; seine Waffe kommt aus dem Inventar (`TOOLGEN`) und wird im Ruhesprite gezeichnet.
- Darstellung: Welt (2D und 3D, `drawHeldTool`, Körper stößt vor oder hüpft über `lift`) und Ego-Perspektive (`drawFpHand`, Viewmodel unten rechts, dazu `kick`/`hop` an der Kamera als Treffergefühl). Das alte Werkzeug-Emoji und die Fäuste sind weg.
- Tragen ist keine Aktion: Imps zeigen Gold und Erz nur noch im Sack auf dem Sprite, das zweite Symbol darüber entfällt.

## 1.18 Balance-Lauf entlang der Kampagne
`tools/balance-campaign.js [maxTicks] [Regionsarten] [Seeds]` startet echte Level mit den Mods aus der Weltwirtschaft für drei Fortschrittsstufen (früh, mitte, spät) gegen eine passende Verteidigung (3, 6, 9 Kreaturen plus Dungeon Lord, 3 Imps, Mauerring) und meldet Kontaktzeitpunkt und Ausgang. Stand: Der erste Kontakt liegt bei etwa 1600 bis 2900 Ticks (Dorf mit Panik 4200). Frühe Dörfer, Farmland, Lager, Schmieden und Festungen sind gegen die kleine feste Verteidigung zu halten, Tore und Hauptstadt fallen früh nach 2000 bis 3900 Ticks, und in der späten Stufe fällt alles nach 1900 bis 4100 Ticks. Ein statischer Dungeon ohne Ausbau, Fallen und Gold ist dafür nur ein grober Maßstab; Eingriffe in die Zahlen brauchen echte Spielläufe.

## 1.19 Legenden und Armeen als Begegnung
- Ruhm = eroberte Regionen + 2 pro Verbündetem (`legendsTurn`, `LEGEND_FAME` = 4 und 8). Bei 4 hören die Legenden (Tor-Bosse) vom Dunkel: ihre Pforte rüstet auf (+1 Welle, +1 Stufe). Bei 8 zieht der Boss selbst als Armee (👑) los und jagt den Spieler; erreicht sie ihn, gibt es +3 Wellen für die nächste Schlacht und er schickt einen benannten Streiter (`campaign.champions`), der in `keepRecruit` ab etwa 60 % des Pools erscheint (1,5-fache Lebenspunkte, bessere Ausrüstung).
- Eine Armee auf dem Zielfeld wird in der Schlacht getroffen (`campaign.encounter`): +3 Wellen, +1 Heldenstufe; bei Sieg verschwindet sie und gibt 1 Fertigkeitspunkt (Legende 2). Die Info einer Region nennt, wenn dort ein Heer steht.

## 1.20 Weitere 3D-Modelle
`MODELS` in `view3d.js` kennt jetzt Thron, Amboss, Esse, Brennofen, Werkbank, Blasebalg, Futtertrog, Kerze und Rundtisch (zusätzlich zu Bett und Regal). Dinge mit Rückseite drehen sich über `FACING_PROPS` von Wänden weg, glühende Öffnungen von Esse und Ofen sind unbeleuchtete Flächen (leuchten also immer). Kleine Haufen (Münzen, Erz, Barren, Hühner) bleiben Sprites.

## 1.21 Ton (`audio.js`)
Alles wird live mit der Web-Audio-API erzeugt (gefilterte Rauschstöße und Töne), keine Klangdateien. `SFX.play(name,{x,y,delay})` ist räumlich: Lautstärke fällt mit der Entfernung zum Hörer (Kamera oder Besessener), links/rechts über Panning, ab 20 Kacheln still. Neuer Klang = neuer Eintrag in `RECIPES`. Eingehängt: Schwünge (`startAnim`, Ton fällt auf den Treffermoment: Hieb, Klopfen, Stampfen, Bauen), Treffer/Krit/Tod (`hitFx`), Wand bricht, Erobern, Bauen (`applyRecipe`), Schritte in der Ego-Ansicht, Horn bei jedem Rekruten am Portal; dazu Dauerbrummen und gelegentliches Tropfen. Stumm schalten mit N oder 🔊 (wird gemerkt). Der Ton startet erst nach der ersten Eingabe (Browserregel). Gehört wurde er bisher nur von Menschen: Tests laufen ohne Lautsprecher.

## 1.22 Einfrieren der Spielwelt, Musik
- Ursache des Einfrierens (UI lebt, Spielfenster steht): `tickLoop` plante den nächsten Tick erst nach `gameTick()`. Warf ein Tick eine Ausnahme, brach die Kette ab und die Spiellogik stand für immer, während Klicks und Rendern weiterliefen. Jetzt wird der nächste Tick zuerst geplant, jeder Teil eines Ticks (jeder Imp, jede Kreatur, jedes `tick*`) läuft einzeln in `guard`, Fehler werden einmalig gemeldet (`reportError`: Konsole und rote Meldung „Fehler im Spiel (läuft weiter)“) und das Spiel läuft weiter. Auch `renderLoop` plant zuerst neu. Geht der WebGL-Kontext verloren (`View3D.onLost`), wechselt das Spiel zur 2D-Ansicht. Die auslösende Ausnahme selbst war in über 70000 Test-Ticks nicht zu finden; die rote Meldung nennt sie jetzt, wenn sie wieder auftritt.
- Musik (`audio.js`, Teil von `SFX`): prozedural und rein synthetisch. Ein Pad auf einer langsamen phrygischen Folge (a, b, a, g), Bass (ein langer Ton, bei Gefahr ein Puls), spärliche Leadnoten per Zufallsgang mit Echo und Hall, Schlagwerk ab Gefahr. `SFX.setIntensity(0..2)` kommt aus `moodLevel()`: 0 ruhig, 1 Helden im Dungeon, 2 Kampf. Das Dauerbrummen ist weg. Musik an/aus mit B oder 🎵, Ton gesamt mit N.

## 1.23 Mehrfach-Tode, versteckte Höhlen, Debug-Werkzeuge
- Fehler „Mira wurde erschlagen“ mehrfach: ein getöteter Gegner blieb als `fightTarget` bei Mitkämpfern hängen und wurde weiter erschlagen (jedes Mal Leiche, Kopfgeld und Logzeile). Jetzt markiert `killCreature` Tote mit `removed` und ist einmalig; `resolveAttack` und die Zielprüfung ignorieren Tote.
- Höhlen, die noch wie Fels aussehen (`natural` und nicht `discovered`), verbargen laufende Körper. `updateFog` deckt jetzt die ganze Höhle auf, sobald dort ein Wesen im Licht steht oder ein eigenes Wesen oder eigener Boden direkt daneben liegt.
- Graben im Unerforschten: schwarze, nie gesehene Felskacheln lassen sich markieren (Rahmen wird auch im Nebel gezeichnet), die Imps graben dort wie sonst.
- Logging und Debuggen: Gleiche Ereignisse zählen hoch (`×n`) statt zu wiederholen. `dbg(kategorie,text)` führt ein getrenntes Protokoll der letzten 800 Zeilen (Ereignisse, jeder Treffer mit Schaden und Restleben, jeder Tod). Im Debug-Bereich: „Nebel ausschalten“, „Fehlerbericht kopieren“ (auch F8: Karte als Text mit Markierungen für versteckte Höhlen, Wesen mit Zustand und Ziel, Fehlerzähler, die letzten Protokollzeilen) und, solange das Debug-Panel offen ist, hängt der Inspektor bei jeder Kachel alle Flags an (`tileDebug`).

## 1.24 Mehr Kreaturen, Fernkampf, sauberere Sprites
- Sprites: keine Schulterplatten mehr (die sahen wie Arme aus). Die Bosse Alberich, Oberon und Artus haben keine festeingebauten Waffen und Schilde mehr; Rüstungsart bleibt als Erkennungszeichen, was sie halten, kommt aus dem Inventar (`bossEq`).
- Gute Seite neu: Bogenschütze, Mönch, Paladin (heilt Verbündete im Umkreis 3), Zwerg (klein, bärtig, zäh), Riese (1,45-fache Größe, `SPECIES.size`). Sprite-Varianten über `vary()` in `sprites.js`. Die Burg zieht sie je nach Räumen und Weltwerten an (`keepPickKind`: Bogenschützen ab Arena, Mönche ab Bibliothek, Zwerge ab Schmiede, Paladine ab zwei Schmieden plus Rüstung ≥2 plus Schlafsaal, Riesen bei hoher Ausbildung später im Level). Die Tore bekommen eigene Pools (Alberich: Zwerge und Bogenschützen).
- Böse Seite neu: Ork, Goblin, Troll, Skelett. Sie nutzen die Warlock-KI (`tickWarlock` mit `HORDE_KINDS`; Forschung nur für Warlocks), haben eigene Vorlieben (`JOB_PREFS`, `LEISURE_PREFS`) und kommen über `LURES`: Orks wegen der Arena (zwei je Arena), Goblins wegen Gold im Lager, Trolle wegen Schmiede oder Schmelze mit Erz oder Eisen. Skelette erheben sich aus alten Leichen (höchstens drei, auch aus Heldenleichen), schlafen und essen nie. Trolle heilen langsam.
- Fernkampf: `reachOf(c)` hängt an der gehaltenen Waffe (Bogen und Armbrust 5, Wurfspeer 3, Zauberstab 4, sonst Nahkampf). Wer eine Fernwaffe hält, bleibt auf Abstand und schießt (`FX.shot`).
- Bisher nicht neu gebalanced: der Heldenmix ist stärker durchmischt (Paladine, Zwerge, Bogenschützen). Die Balance-Skripte laufen ohne Fehler, aber die Zahlen aus Abschnitt 1.18 stammen vom alten Mix.

## 1.25 Fertigkeitspunkte und der Tod des Dungeon Lords
- Fertigkeiten: Tabelle `SKILLS`, gespeichert in `campaign.skills`. Jeder Punkt wirkt prozentual (`skillMult`): Lord-Leben und -Stärke, Lord-Reserve, Kreaturen-Leben und -Stärke (alle Wesen der Spielerseite, auch Imps), Imp-Tempo, Startgold. Ausgeben auf der Weltkarte (Knopf in der rechten Leiste), ohne Rückgabe. Die Stufe des Lords hängt jetzt an den eroberten Regionen, nicht mehr an den Punkten.
- Tod des Lords: Fällt er auf 0, bleibt er nicht tot, sondern wird in den Thronsaal teleportiert und ist bewusstlos (`faintLord`). Dort ist er für die Helden angreifbar; Treffer gehen von `state.war.lordPool` ab (Start: sein Maximalleben mal Reserve-Fertigkeit). Ist die Reserve leer, ist der Run verloren (`lostBy:'lord'`). Nach `LORD_FAINT_TICKS` steht er mit halbem Leben wieder auf. Die HUD-Zeile „Dungeon Lord“ zeigt Leben oder „bewusstlos · Reserve“. Besessene Lords werden beim Umfallen freigegeben.

## 1.26 Nebenziele und Artefakte
- `artifacts.js`: Tabelle `ARTIFACTS` (Name, Seltenheit, Platz `weapon`/`armor`/`charm`, `item` aus `ITEMS`, `ranks` = geschenkte Fertigkeitsränge, `curse` = Preis als dauerhafte Heldenmacht). `rollArtifact(rng,progress)` würfelt die Seltenheit nach Fortschritt (höchstens episch), Legendäre kommen nur von Pforten (`GATE_REWARDS`: direkter Weg Trophäe, listiger Weg legendär). `skillRank` addiert `artifactRanks`, `lordArtifactGear` gibt dem Lord die beste Waffe und Rüstung.
- Nebenziele: `sideGoal` je Regionsart, geprüft in `tickWar` über `SIDE_GOALS` (`objectives.js`). Fortschritt in `state.war` (`takenTiles`, `heroKills`, `knightDead`). Die Zielbox im Level zeigt den Stand. Beim Sieg plant `planReward` (seedbasiert, also nicht neu würfelbar) die Beute, `finishLevel` gibt sie, wendet den Preis an (`campaign.curse`, in `OW.power`) und meldet sie im Bericht. Die Weltkarte hat einen Knopf „Artefakte“.

## 1.27 Das Finale: Herakles in der Hauptstadt
`setupCapitalHall` (in `LEVEL_SETUPS`, Setup der Region `capital`): große ummauerte Halle (17×13) mit einem Tor, in der Mitte Herakles (`herakles`, Boss, Größe 1,3), vier Wächter (Paladine) und am Altar gegenüber das Löwenfell (`t.pelt`, Prop `pelt`). Zwei Wege wie bei den Pforten: direkt (`defeat_boss`) oder listig (`steal_pelt`: Fell nehmen, dann korrumpieren). Solange das Fell hängt, erleidet Herakles nur ein Viertel Schaden (`resolveAttack`). Bei halbem Leben tobt er (`tickBoss`: 1,4-faches Tempo, ruft Paladin, Ritter, Bogenschütze). Rezept `take` (jede Figur der Spielerseite). Die Helden kommen aus dem Tor mit dem Pool der Hauptstadt; der Sieg beendet den Run mit einer Meldung (`finishLevel`).

## 1.28 Gefängnis und Bekehren
- Raum `prison` (mindestens 4 Felder, Zellen auf jedem zweiten Feld), Forschungsthema `prison` (Warlocks bekommen die Idee beim Anblick eines bewusstlosen Helden). Textur `prison`.
- Bewusstlose Helden (nicht Bosse) trägt ein Imp (`CARGO.prisoner`, Job `findPrisonerJob`, vor Verstärken und Füttern) in eine freie Zelle; dort ist er `imprisoned`, wacht nicht auf (`tickUnconscious` ruft `tickPrisoner`). Der Fortschritt läuft mit 1 pro Tick, plus 0,5 für jedes Wesen der Spielerseite im Umkreis 3 (höchstens +2), und ist erreicht bei 420 plus 80 pro Stufe. Dann `convertPrisoner`: der Held wird Kreatur des Spielers (`corrupted`, Kategorie humanoid, bekommt Bedürfnisse und Lager, nutzt die Warlock-KI, trägt weiter seine Ausrüstung, Sprite `<art>_ally` mit Spieleraugen und dunklerer Kleidung). Fällt ein Imp mit Gefangenem, wird der Gefangene wieder abgelegt.
